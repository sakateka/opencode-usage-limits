# opencode-usage-limits

[English](README.md) | [Русский](README.ru.md)

TUI-плагин для OpenCode V2: показывает лимиты **Kimi Code**, **OpenAI/Codex**,
**Z.AI Coding Plan** и **OpenCode GO** в сайдбаре и компактный индикатор в футере
промпта.

Запросы выполняются через общий HTTP-клиент с ограничением размера ответа и
таймаутом. Плагин не запускает внешние процессы и не записывает учётные данные.
Основной пример настройки — подписка **Kimi Code через kimi.ai**.

## Возможности

- Блок `Usage Limits` в сайдбаре с процентами расхода и временем сброса квот.
- Индикатор активного провайдера сессии в футере промпта.
- Интервал обновления настраивается; по умолчанию — 5 минут после завершения опроса.
- Опрашивается только включённый провайдер выбранной модели. Смена провайдера
  запускает обновление сразу; неподдерживаемые провайдеры не опрашиваются.
- Скрытие сайдбара не останавливает обновление футера.
- `/limits` принудительно обновляет лимиты и открывает локальный диалог.
  Команда и результат не добавляются в историю разговора и контекст модели.
- Отдельные настройки показа окон и полос прогресса для каждого провайдера.
- Сохранение последнего успешного результата при временной ошибке API.
- Для Kimi — фиксированный официальный HTTPS-адрес и запрет перенаправлений.

## Установка из GitHub без публикации на npm

Нужны Git, [Bun](https://bun.sh/) и OpenCode V2. Загрузка из локального каталога
проверена с OpenCode **2.0.32**. Команды ниже предназначены для Linux/macOS.
Если репозиторий приватный, потребуется доступ на чтение.

Команды `npm`, глобальные ссылки на пакеты и `opencode plugin add` не нужны.
При этом Bun скачивает зависимости из npm-реестра: это установка **без публикации
самого плагина на npm**, а не полностью автономная установка без реестра.

### 1. Клонировать и собрать

Для примера с SSH заранее настройте GitHub SSH-ключ. Если репозиторий приватный,
ключ должен иметь доступ на чтение. Не добавляйте токены GitHub в URL.

```sh
git clone git@github.com:sakateka/opencode-usage-limits.git "$HOME/.local/share/opencode-usage-limits"
cd "$HOME/.local/share/opencode-usage-limits"
bun install
bun run build
```

Для публичного репозитория можно использовать HTTPS без SSH-ключа:

```sh
git clone https://github.com/sakateka/opencode-usage-limits.git "$HOME/.local/share/opencode-usage-limits"
```

Это альтернативная команда клонирования, а не дополнительный шаг. Затем так же
перейдите в каталог и выполните `bun install` и `bun run build`.

Не удаляйте рабочую копию после сборки: OpenCode загружает плагин прямо из неё.
Файл `tui.ts` в корне переэкспортирует собранный `dist/index.mjs`. Для загрузки
каталога этот файл необходим: одного экспорта `./tui` в `package.json` недостаточно.

### 2. Подключить локальный каталог

Добавьте запись в `~/.config/opencode/cli.json`, сохранив остальные настройки и
уже подключённые плагины. Замените `/home/YOU` на свой домашний каталог; на macOS
обычно используется `/Users/YOU`. Нужен **абсолютный путь**, без нераскрытого `~`.

```jsonc
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "plugins": [
    { "package": "/home/YOU/.local/share/opencode-usage-limits" }
  ]
}
```

Не указывайте вместо пути `opencode-usage-limits` или
`@sakateka/opencode-usage-limits`: имя пакета запускает установку из реестра,
а не загрузку этой рабочей копии. Нескоупленное имя `opencode-usage-limits`
принадлежит другому npm-пакету.

### 3. Настроить подписку Kimi Code через kimi.ai

Создайте `~/.config/opencode/usage-limits.jsonc`:

```jsonc
{
  "enabled": true,
  "refreshIntervalSeconds": 300,
  "requestTimeoutMs": 10000,
  "showErrors": true,
  "providers": {
    "kimi": {
      "enabled": true,
      "label": "Kimi Code",
      "apiKey": "{env:KIMI_CODE_API_KEY}",
      "sidebarWindow": "all",
      "footerWindow": "auto"
    }
  }
}
```

В этом примере включён только глобальный **Kimi Code**. Это лимиты подписки,
не баланс платного Moonshot API. Готовый пример также есть в
[`examples/usage-limits.jsonc`](examples/usage-limits.jsonc).

Создайте API-ключ подписки в [консоли Kimi Code](https://www.kimi.com/code/console).
Адрес запроса фиксирован: `https://api.kimi.ai/coding/v1/usages`.
Поле `baseUrl` не требуется и для Kimi не поддерживается.

Переменная `KIMI_CODE_API_KEY` должна быть доступна процессу **TUI OpenCode**.
Например, в **Bash** можно ввести ключ без отображения на экране и без сохранения
самого значения в истории команд:

```bash
read -r -s -p 'Kimi Code API key: ' KIMI_CODE_API_KEY
echo
export KIMI_CODE_API_KEY
opencode
```

В новом терминале экспорт нужно повторить либо использовать свой менеджер
секретов. Не коммитьте настоящие ключи, токены и файлы авторизации, даже в приватный
репозиторий.

Если в старом `~/.local/share/opencode/auth.json` уже есть пригодная запись
`kimi-code-plan-global`, она имеет приоритет над ключом из переменной окружения.
Явно заданный `authPath` имеет приоритет над обоими источниками.

**Ограничение:** плагин пока не читает хранилище учётных данных OpenCode V2 в
SQLite. Если аккаунт существует только там, используйте ключ через переменную
окружения; редактировать или экспортировать базу данных не нужно.

### 4. Проверить работу

Перезапустите TUI. В `/plugins` должен появиться **`sakateka.usage-limits`** с
локальным источником и без ошибки. В открытой сессии сайдбар покажет Kimi Code:
окна за 5 часов и за месяц, проценты расхода и время сброса, если API его сообщает.
Месячная общая квота и месячная квота кода отображаются отдельно.

Индикатор в футере появляется для сессий с провайдером `kimi-code-plan-global`.
Для просмотра всех включённых провайдеров в сайдбаре переключать модель не нужно.

Если что-то не отображается:

- Откройте палитру команд и выберите **Show sidebar**; терминал должен быть
  достаточно широким.
- Если плагина нет в списке, проверьте абсолютный путь, `tui.ts` в корне и
  наличие `dist/index.mjs` после сборки.
- `missing Kimi Code key` — проверьте переменную окружения процесса TUI.
- HTTP `401` — API квот отклонил выбранный ключ. Учтите, что старая запись в
  `auth.json` может иметь приоритет над новым ключом из окружения.

### Обновление

```sh
cd "$HOME/.local/share/opencode-usage-limits"
git pull --ff-only
bun install
bun run build
```

После сборки перезапустите TUI. Публикация в реестр и перезапуск фонового сервера
не требуются.

### Остальные провайдеры

Добавляйте в объект `providers` только нужные записи:

```jsonc
"codex": { "enabled": true },
"zai": { "enabled": true },
"opencode-go": { "enabled": true }
```

Для каждого провайдера нужны собственные рабочие учётные данные. Ключ Kimi не
используется для других сервисов.

## Поддерживаемые провайдеры

| ID в конфиге | API | Окна квот | Учётные данные |
| --- | --- | --- | --- |
| `kimi` | `https://api.kimi.ai/coding/v1/usages` | 5 часов, месяц всего, месяц для кода; старый формат — неделя | `kimi-code-plan-global` в старом OpenCode auth либо конфиг |
| `codex` | `https://chatgpt.com/backend-api/wham/usage` | основное, дополнительное, кредиты сброса | старый OpenCode auth `openai`, `~/.codex/auth.json` либо конфиг |
| `zai` | `https://api.z.ai/api/monitor/usage/quota/limit` | кредиты за 5 часов и неделю; старый формат токенов | старый OpenCode auth `zai-coding-plan`/`zai` либо конфиг |
| `opencode-go` | `https://opencode.ai/zen/go/v1/usage` | скользящее, неделя, месяц | старый OpenCode auth `opencode-go`/`opencode` либо конфиг |

## Безопасность и формат Kimi Code

- Официальный [клиент Kimi](https://github.com/MoonshotAI/kimi-cli/blob/main/src/kimi_cli/ui/shell/usage.py)
  использует `GET <coding base URL>/usages` с Bearer-авторизацией. Глобальный
  адрес описан в [документации Kimi Code](https://www.kimi.com/code/docs/en/#api-access).
- Поддерживаются поля `usages.limit_5h`, `limit_month_total` и `limit_month_code`
  с `used_ratio` и `reset_time`. Точные доли имеют приоритет над округлёнными
  счётчиками старого `limits[].detail`.
- Ключи остаются в `Redacted` до передачи HTTP-клиенту. Нет подмены URL,
  чтения cookies браузера, внешних команд или автоматического входа в аккаунт.
- Общий HTTP-клиент ограничивает тело ответа до 2 МиБ, применяет настроенный
  таймаут и поддерживает отмену. Kimi-адаптер запрещает перенаправления.
- Тела ошибок и учётные данные не выводятся в логи.

## Разработка

```sh
bun install
bun run typecheck
bun run test
bun run build
```

Текущий тестовый скрипт запускает Vitest под Node. UI-тестам нужна версия Node с
экспериментальным FFI: флаг `--experimental-ffi` уже задан в скрипте, тесты проверены
на Node 26. Для работы плагина внутри OpenCode отдельный Node не требуется.
